# 작업 사이클

코드를 바꾸는 작업의 처음부터 끝까지를 한 절차로 묶는다.

**스킬은 안내하고, 훅이 강제한다.** 어느 한쪽만으로는 안 된다 — 안내만 있으면 건너뛰게 되고, 강제만 있으면 무엇을 해야 할지 모른다.

## 사이클을 시작한다

작업 범위를 파악한 **뒤에** 상태 파일을 만든다. 파일이 존재하는 순간부터 `cycle-stop.sh` 가 세션 종료를 막기 시작하므로, 무엇을 할지 모르는 채로 만들지 않는다.

```
git switch -c <브랜치이름>
printf 'branch=%s\nround=0\nmax_rounds=3\nreview=pending\nverify=pending\nharness_touched=no\n' \
  "$(git rev-parse --abbrev-ref HEAD)" > .claude/.cycle-state
```

`max_rounds` 는 리뷰→수정 라운드 상한이다. 수렴하지 않는 것을 무한히 돌리지 않기 위한 것이고, 상한에 닿으면 사람을 부르고 멈춘다.

## 단계

### ① 브랜치

`main`/`master` 에서 `src/` 를 고치려 하면 `branch-guard.sh` 가 **ask** 로 한 번 묻는다. 차단이 아니다 — 같은 브랜치에서 한 번만 뜬다.

### ② TDD 구현

`tdd-guard.sh` 가 본체 `.kt` **신규 생성**을 막는다. 통과 조건은 그 클래스 이름을 언급하는 테스트가 `src/test/kotlin` 어딘가에 있는 것이다.

- `Write`·`Edit` 뿐 아니라 **`touch`·`cp`·`mv`·`dd`·리다이렉션·`tee`·MCP 쓰기 툴**도 같이 막힌다. 툴을 바꿔 우회하려 하지 마라.
- 막히면 답은 **로직을 순수 클래스로 빼내 테스트하는 것**이다. 면제 목록에 추가하는 것이 아니다.
- `.claude/tdd-exempt.txt` · `tdd-baseline` · 훅 스크립트 · `check.sh` 를 고치려 하면 **ask** 가 뜬다. 이건 게이트 자신이기 때문이다. 이 사이클에서 그걸 고쳤다면 `harness_touched=yes` 를 상태에 남기고, 마지막 보고에 왜 고쳤는지 적는다.

새 테스트를 만들면 `tdd-red.sh` 가 그 테스트만 돌려 **실패(red)하는지** 확인한다. 처음부터 통과하면 그 테스트는 아무것도 지키지 않는다.

### ③ 리뷰

`sheet-reviewer` 에이전트에게 맡긴다. 끝나면 `cycle-review.sh` 가 보고서의 `### 🔴` 섹션을 세어 상태에 기록한다:

- 항목이 있으면 `review=red:N`, 라운드가 1 오른다
- 없으면 `review=clean`
- 보고 형식을 못 읽으면 `review=unknown` — 이건 통과가 아니다. 사람이 확인해야 한다

### ④ 수정

지적을 고친다. **지적을 없애려고 테스트나 면제 목록을 고치지 마라.** 반복 루프는 저항이 가장 적은 경로로 수렴하는데, 그 경로가 정확히 이것이다. 그래서 게이트 파일 수정에 `ask` 가 걸려 있다.

고친 뒤 ③ 으로 돌아간다.

### ⑤ 샌드박스 검증

`review=clean` 이 된 뒤에 `sandbox-runner` 에이전트에게 `sandbox-verify` 스킬로 맡긴다. 기계가 볼 수 있는 것만 본다 — 플러그인 로드와 구간 로그의 예외·EDT 블로킹·누수.

**표가 제대로 그려졌는지는 여기서 알 수 없다.** 그건 ⑦ 에서 사람이 본다.

### ⑥ 반복

`verify=red:N` 이면 고치고 ③ 부터 다시. 라운드가 `max_rounds` 에 닿으면 자동으로 멈추고 사람을 부른다.

### ⑦ 인계

`review=clean` 이고 `verify=clean` 이면 `cycle-stop.sh` 가 더 이상 막지 않는다. 마지막으로 **사람이 직접 볼 수 있게 샌드박스를 띄운다** — 이번에는 `sandbox-run` 스킬이다(자가검증이 아니라 인계 절차다).

띄운 뒤 사이클 상태를 정리한다:

```
rm -f .claude/.cycle-state
```

커밋 전에는 `./scripts/check.sh` 통과 → `.claude/tdd-baseline` 갱신. 커밋은 사람이 결정한다.

## 막혔을 때

- **세션이 안 끝난다**: `cycle-stop.sh` 가 되돌리는 중이다. stderr 에 남은 단계가 적혀 있다. 3번 되돌리면 포기하고 통과시킨다. 그만두려면 `rm -f .claude/.cycle-state`.
- **리뷰가 `unknown`**: 리뷰어가 보고 형식을 벗어났다. 다시 시키거나 사람에게 묻는다.
- **샌드박스가 안 뜬다**: 같은 명령을 다시 던지지 마라 — 두 번째는 첫 번째 Gradle 락에 걸린다. `sandbox-up.sh status` 로 확인하고 `down` 으로 정리한다.
- **테스트가 red 인데 내 변경과 무관해 보인다**: `TODO.md` 의 진행 중인 기능이 테스트를 먼저 올려 둔 상태일 수 있다. 내 변경분만 돌려 본다.

## 사이클을 쓰지 않아도 되는 경우

문서만 고치는 작업, 오타 수정, `TODO.md` 갱신에는 사이클이 필요 없다. 상태 파일을 만들지 않으면 훅들은 **아무 일도 하지 않는다.**
